Technical Specification: Agentic Medical Device Documentation System (Med-Agentic)
This document outlines the technical architecture and implementation strategy for an AI-driven system designed to automate the extraction, management, and review of Medical Device Instruction For Use (IFU) documents. The system leverages Agentic AI to transform unstructured PDFs into structured data, facilitating advanced search, compliance auditing, and administrative workflows.

1. System Overview
The Med-Agentic System is a web based application deployed on Hugging Face Spaces. It utilizes Streamlit for the frontend, Gemini and OpenAI api for reasoning and extraction, and an agent-based architecture defined by agents.yaml and SKILL.md.

1.1 Core Objectives
Automation: Convert PDF IFUs into structured JSON.

Searchability: Provide granular search across license numbers, manufacturers, and technical specifications.

2. Technical Architecture
The system follows a modular "Agent-Tool" pattern where a coordinator agent delegates tasks to specialized sub-agents.

2.1 Technology Stack
Component	Technology
Hosting	Hugging Face Spaces (Docker/Streamlit SDK)
Frontend	Streamlit
Orchestration	Python-based Agent Framework (inspired by CrewAI/LangGraph)
LLMs	Google Gemini (Multimodal), OpenAI 

3. Data Ingestion & Transformation (Requirement I & III)
3.1 Automated PDF Extraction
To process 10,000+ records, the system employs a Batch Extraction Agent.

Mapping: It maps text to specific chapters: Product Description, Intended Use, Indications, Specifications, Dosage/Usage.

Output: Validated JSON schema 

3.2 CSV/Batch Import
The system provides a high-throughput endpoint for CSV imports.

3.3 Visual Table Editor
A Streamlit-based data editor (st.data_editor) allows manufacturers to manually adjust extracted "Specification/Model" tables. This ensures 100% accuracy for critical technical data that may be misread by OCR.

4. Agentic Configuration (agents.yaml & SKILL.md)
The system's behavior is governed by two core configuration files.

4.1 SKILL.md (System Prompt)
This file acts as the "Brain" and "Legal Expert" for the agents. It contains the logic for Taiwan FDA (TFDA) regulatory standards.

Markdown

# SKILL: Medical Device Regulatory Specialist

## Role
You are an expert in Medical Device Regulations and Document Engineering. Your goal is to ensure all Instructions for Use (IFU) are parsed with 99.9% accuracy into structured JSON.

## Extraction Rules
1. **Product Name:** Must extract both Chinese and English titles.
2. **Date Format:** Convert all dates to YYYY-MM-DD.
3. **Difference Analysis:** When comparing two versions, focus on "Intended Use" changes. If the scope of use has expanded, flag it as a "Major Change."

## Search Logic
- For "Advanced Search," interpret Boolean logic (AND, OR, NOT) within the metadata filters.
- Use fuzzy matching for manufacturer names to account for slight spelling variations.
4.2 agents.yaml (Agent Definitions)
This defines the workforce hierarchy.

YAML

agents:
  - name: "ExtractorAgent"
    role: "Multimodal Data Specialist"
    llm: "gemini-1.5-pro"
    skills: ["PDF_Parsing", "JSON_Structuring"]
    description: "Responsible for converting raw PDFs and images into structured JSON chapters."

  - name: "AnalystAgent"
    role: "Compliance Reviewer"
    llm: "gpt-4o"
    skills: ["Text_Diffing", "Change_Classification"]
    description: "Compares current IFU with historical records to highlight changes."

  - name: "SearchAgent"
    role: "Information Retrieval Expert"
    llm: "gpt-4o"
    skills: ["SQL_Generation", "Vector_Search"]
    description: "Translates natural language queries into complex database filters."
5. Web Interface Design (Requirement II)
The UI is built with Streamlit for rapid deployment on Hugging Face.

5.1 Search Interface
Simple Search: A single bar supporting License ID or Product Name.

Advanced Search: A sidebar with dynamic fields:

Query Type: General Medical vs. IVD.

Boolean Logic: Multi-select inputs for complex filtering.

5.2 Results & Structured View
The results table displays key metadata and action buttons.

Expandable Sections: Uses st.expander for each chapter (Product Description, Specifications, etc.).

Visual Assets: Images of "Outer Box" and "Labels" are displayed using a gallery component.

6. Intelligent Review Features

7. Technical Implementation Details
7.1 PDF Export
The system uses ReportLab or WeasyPrint to generate official PDFs from the structured JSON, ensuring that the exported version reflects the "Approved" state of the document without internal notes.
